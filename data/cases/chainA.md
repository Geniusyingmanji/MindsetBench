# 线程 A 完整迁移链：A-chain-01

> 目的（SPEC §7 缺口 3）：同一 Schema 贯穿 L1→L4 的单线程完整链，四个目标题共享同一个源题，用于画单线程迁移梯度曲线（增益(L1)…增益(L4) 的衰减率）。
> 固定图式 Schema："解的可行域被多条显式约束与隐式约束共同切割；隐式约束不写在约束清单里、必须从题面语义中主动挖掘出来并逐一用于切割，遗漏任何一条隐式约束就会多算/漏算。"
> 结构距离设计：L1 仅翻 Surface；L2 翻 Surface+Domain（Model/Method 严格同构）；L3 再翻 Model/Method（切割算子换形+新增隐式上限，照搬会错）；L4 除 Schema 外全翻（模型与算子全异）。严格单调递增。
> 全部数值答案（含 L3 照搬错误答案、各级"遗漏隐式约束"的多算探针）已用 python3 穷举验证，逻辑记录于各题 verified 字段。

## 共享源题（数学·组合几何计数）

题面：周长为 48 的三角形，三条边长都是正整数且两两不相等（不等边三角形）。彼此全等的只算一种（即不计三边的排列顺序）。问这样的三角形共有多少个？

解答（显式暴露图式）：
1. 列显式约束：不计顺序即规范化排序，设三边为整数 a < b < c（两两不等由题面给出）。显式约束只有两条：a + b + c = 48；a, b, c 两两不等。
2. 挖隐式约束：题面没写、但"能构成三角形"蕴含 ① 每边为正整数 a ≥ 1；② 三角形不等式 a + b > c（排序后另两条自动成立），等价于 c ≤ 23；又因 c 是严格最大边，c ≥ 17（c > 48/3）。隐式约束才是切割可行域的主刀：若遗漏 a + b > c，满足"和为 48 且两两不等"的 (a<b<c) 共有 169 组——会把 132 组根本拼不拢的退化三元组也算进去（多算）。
3. 逐一切割枚举：按最大边 c = 17..23 分层，对每个 c 数满足 a + b = 48 − c、a < b < c 的 (a, b) 对数：c=17:1，18:2，19:4，20:5，21:7，22:8，23:10。
4. 合计：1+2+4+5+7+8+10 = 37。

答案：37

## L1-A-C1｜同域变型｜数学 → 数学（剪铁丝焊框架）

翻转：仅 Surface（故事从抽象三角形换成剪铁丝焊框架，参数 48→54）；Domain/Model/Method/Schema 全同。

### 目标题（数学·组合几何计数）
一根长 54 厘米的铁丝要剪成三段，每段都是整厘米数且三段长度互不相同，然后把三段首尾相焊做成一个三角形框架。只关心得到的三段长度的组成（不计剪的先后顺序），问能真正焊成三角形框架的剪法共有多少种？

答案：48（数值）

### 对应关系
- 周长 48 ↔ 铁丝总长 54；三边 ↔ 三段；"能构成三角形" ↔ "能焊成框架"（三角形不等式仍是隐式的，藏在"焊得拢"里）。
- 解法逐字对应：挖出 a+b>c ⟺ 最长段 ≤ 26，按最长段 c = 19..26 分层枚举。遗漏隐式约束的多算探针：217（真值 48）。

lure：无（SPEC 规定 L2 起配 lure）。
verified：python3 穷举 a<b<c、a+b+c=54、a+b>c 得 48；去掉三角形不等式得 217。断言通过。

## L2-A-C1｜跨科同构｜数学 → 公司治理/公司法

翻转：Surface + Domain；Model/Method 严格同构——剥掉股权外衣后就是"总量 60 的不等边三角形计数"，且隐式约束需从表决语义中重新推导出来（对应源题从"构成三角形"中挖出三角形不等式）。

### 目标题（公司治理/公司法）
某创业公司共发行 60 股表决权股，由三位联合创始人全部持有，每人都实际持有股份，且三人持股数互不相同（章程为避免表决僵局作此要求）。股东会决议以简单多数通过（所持股数过半，即至少 31 股赞成才通过）。投资人尽调条款要求：任何一位创始人都不得拥有"单边控制力"——既不能仅凭自己的股份使决议通过，也不能仅凭自己的股份阻止其余股东联合通过决议。问满足全部要求的持股结构（三个持股数的组成，不区分具体是谁）共有多少种？

答案：61（数值）

### 对应关系（同构映射）
| 源（三角形） | 目标（股权） |
| --- | --- |
| 周长 48 | 总表决权 60 股 |
| 三边 a<b<c | 三位创始人持股 |
| 隐式：三角形不等式 c < a+b ⟺ c ≤ 23 | 隐式：无单边控制力 ⟺ x ≤ 29 ⟺ x < 其余两人之和 |
| 隐式：每边 ≥ 1 | 隐式："每人都实际持有" ⟺ x ≥ 1 |
| 显式：两两不等 | 显式：反僵局条款 |

推导（对应源题第 2 步）：单独阻止 ⟺ 其余两人合计 60−x ≤ 30 ⟺ x ≥ 30；单独通过 ⟺ x ≥ 31。故"无单边控制力" ⟺ x ≤ 29 ⟺ 每人严格小于其余两人之和——与三角形不等式逐字同构。按最大持股 c = 21..29 分层枚举：1+2+4+5+7+8+10+11+13 = 61。

### Lure（同学科·异结构）
"三位创始人分 60 股表决权股，每人至少 1 股、三人持股互不相同，问持股结构（不区分身份）共有多少种？【解答】枚举最大者直接计数，得 271。"
- 表面相似：同为三人分 60 股的整数计数、同样要求互不相同。
- 结构不同：没有"控制力"语义 ⇒ 可行域未被隐式上界 x ≤ 29 切割，不是三角形结构；照搬其计数到目标题得 271（多算 210 种含单边控制力的结构），真值 61。

verified：python3 穷举 a<b<c≥1、和 60、每股 ≤29 得 61，与"不等边三角形周长 60"计数完全一致（同构成立）；无条款版 271。断言通过。

## L3-A-C1｜跨域近同构｜数学 → 医疗排班/劳动合规

翻转：Surface + Domain + Model（切割算子换形）+ Method（需适配）；Schema 同。核心关系保持：总量守恒的整数分配、严格排序规范化、每个个体被其余个体约束切割、隐式约束必须先挖出。但切割结构有实质差异，照搬源解法会错。

### 目标题（医疗排班/劳动合规）
某医院重症科 11 月（共 30 天）的 66 个值班班次全部由甲、乙、丙三名护士承担，每人每天最多值 1 个班。此外每人当月必须完成 4 个整天的脱产培训，培训日全天不能值班。三人资历甲 > 乙 > 丙，科室惯例要求资历越高当月班次严格越多。工会公平条款：任何一人的班次数不得超过其余任何一人的 2 倍。问满足全部要求的班次分配方案 (甲, 乙, 丙) 共有多少种？

答案：12（数值）
（全部 12 组解：(26,25,15) (26,24,16) (26,23,17) (25,24,17) (26,22,18) (25,23,18) (26,21,19) (25,22,19) (24,23,19) (25,21,20) (24,22,20) (23,22,21)）

### 照搬为什么错、需要怎么改
- 照搬（错误答案 = 75）：把目标题当"周长 66 的不等边三角形"计数——用加法支配切割"每人 < 其余两人之和"（⟺ 甲 ≤ 32），按最大者分层枚举得 75。错在两处：目标题的切割不是加法支配而是乘法比例耦合（任何一人 ≤ 任何另一人的 2 倍 ⟺ 甲 ≤ 2×丙，上界随最小者浮动，不存在固定闭式上界）；且叙述里还藏着一条日历隐式上限——每人最多值 30 − 4 = 26 个班。
- 部分照搬（错误答案 = 33）：用了比例条款但漏挖日历上限（甲最大可到 32 > 26），仍多算 21 种。
- Model 哪里变了：切割算子从"c < a + b（对称加法支配，等价于固定上界 ⌊(n−1)/2⌋）"变为"甲 ≤ 2丙（比例耦合，上界依赖最小分量）∧ 各分量 ≤ 26（叙述中挖出的绝对上限）"，二者联合切割，源题的"先解出最大边闭式范围再分层"失效。
- Method 需要哪步适配：不能先定最大者的闭式区间；须按最小者丙分层（或三重枚举），对每个丙取甲的上界 min(2丙, 26) 再逐条核验排序与总和——枚举方向与裁剪条件都要重排。

### Lure（照搬天真版·排班表皮、源结构）
"另一科室把本季度的 66 个机动班次分给三名资历严格递减的护士（资历高者班次严格更多，每人至少 1 个班），唯一规则：任何一人的班次必须严格少于其余两人之和。问分配方案数？【解答】最大者 ≤ 32，按最大者分层枚举得 75。"
- 表面相似：同为三名护士、同为 66 个班次、同为资历严格排序下的整数分配计数。
- 结构不同：切割是加法支配（三角形结构），无比例耦合、无日历隐式上限；照搬其解法到目标题得 75（错误），真值 12。

verified：python3 三重穷举：真值 12（12 组解全部列出核对）；只用支配切割（照搬）= 75，与"不等边三角形周长 66"计数一致；用比例条款但漏日历上限 = 33（甲最大到 32，证明隐式上限确实切掉了解）。断言 12 < 33 < 75 通过。

## L4-A-C1｜跨域远类比｜数学 → 网络安全/系统运维

翻转：Surface、Domain、Model、Method 全异，仅共享 Schema。Model 从"单一等式 + 序 + 支配的整点计数"变为"子集选择 + 逻辑蕴含闭包 + 预算不等式的组合最优化"；Method 从"规范化排序、按最大元分层枚举、计数"变为"从叙述推导依赖闭包与互斥、对 2⁸ 个子集搜索/剪枝、求最大可行子集"。共享的只有图式：可行域被显式预算与必须自行挖掘的隐式约束（依赖闭包、端口互斥、空转判定）共同切割，遗漏任何一条隐式约束就会多算可启用集合。

### 目标题（网络安全/系统运维）
公司要在一台对外应用服务器上部署服务，可用内存预算 2048 MB。候选服务与常驻内存占用：反向代理 A（256）、站点应用 B（512）、数据库 C（512）、查询缓存 D（256）、备份代理 E（128）、监控探针 F（128）、旧版 FTP 服务 G（256）、入侵检测系统 H（512）。运维手册里记着几条现状说明（并未整理成约束清单）：
1. 站点应用 B 的所有动态数据都读写于数据库 C，其对外流量必须全部经反向代理 A 转发——缺 A 或缺 C 时 B 无法对外提供任何功能；
2. 查询缓存 D 只缓存 B 的查询结果，B 不在时 D 只会空转；
3. 备份代理 E 与旧版 FTP 服务 G 都硬编码监听 21 端口，均无法改配置；
4. 公司安全基线规定：凡运行数据库 C 的服务器必须同时运行入侵检测系统 H；
5. 除上述说明外，各服务均可独立运行并发挥各自功能，无其他依赖或冲突。

"有效启用"指服务运行且能发挥其功能（空转不算）。问：(i) 这台服务器最多能同时有效启用多少个服务？(ii) 取得该最大数时内存共占用多少 MB？答案格式："个数;内存MB"，如 "4;1024"。

答案：6;2048（字符串，双段式防蒙对；唯一最优子集 {A, B, C, E, F, H}）

### 图式级对应（仅 Schema 保持）
- 显式约束：内存预算 ≤ 2048（↔ 源题的周长等式，连等式/不等式形态都不同）。
- 隐式约束（必须自行挖掘，遗漏任何一条 → 以为能开 7 个）：① 依赖闭包 B ⇒ {A, C}，D ⇒ B（进而 ⇒ A, C）；② 安全基线传递 C ⇒ H；③ 端口互斥 E ⊕ G；④ "空转不算有效启用"的判定语义。
- 关键推理链（对应源题"挖隐式→切割"两步）：开满 7 个必须弃掉 E/G 之一，但弃 G 后内存 2304 > 2048、弃 E 后 2432 > 2048，故 7 不可行；6 个的唯一可行解是弃 {G, D}——{A,B,C,E,F,H} 恰好 2048 MB，其余任何 6 元组合要么破坏依赖闭包、要么超预算、要么端口冲突。
- 对象映射非平凡：没有"总量守恒""三方排序""最大元"的对应物；答案形态从计数变为（最优值, 伴随资源）双段。

### Lure（同域·异图式）
"一台内网工具机内存 2048 MB，从八个互不相关的独立小工具（内存 128、128、256、256、256、512、512、512 MB）中选装尽可能多个。【解答】单预算装填：按内存升序贪心装入，128+128+256+256+256+512+512 = 2048，最多装 7 个。"
- 表面相似：同为服务器按内存预算选服务，内存清单与预算数字与目标题完全相同。
- 结构不同：图式是"单一显式预算下的装填贪心"，无任何隐式约束需要挖掘；照搬贪心到目标题会答 7（错误）——其所选集合 E 与 G 端口冲突、C 无 H 违反安全基线、D 依赖闭包不完整，真值 6（且伴随内存 2048）。

verified：python3 枚举全部 2⁸ = 256 个子集，核验依赖闭包（B⇒A,C；D⇒B）、安全基线（C⇒H）、端口互斥（¬(E∧G)）与预算：7 个的可行解为空集；6 个的可行解唯一 = {A,B,C,E,F,H}，内存恰 2048；升序贪心（忽略结构）得 7。断言通过。

## 难度持平性说明（增益差异归因控制）

链的核心设计目标是：四个目标题与源题的结构距离严格单调递增（L1 仅 Surface → L2 Surface+Domain → L3 Surface+Domain+Model+Method（部分） → L4 除 Schema 全翻），而题目本身的难度（计算量/步数）尽量持平，使 with-source 增益的衰减只归因于迁移距离、不归因于题目难度漂移。持平性从四个维度控制：

| 维度 | 源题 | L1 | L2 | L3 | L4 |
| --- | --- | --- | --- | --- | --- |
| 枚举规模（切割后状态数） | 7 层 / 37 解 | 8 层 / 48 解 | 9 层 / 61 解 | 三重枚举有效分支 ~10² / 12 解 | 256 子集 / 唯一最优 |
| 约束条数（显式+隐式） | 2+2 | 2+2 | 2+2 | 3+2 | 1+4 |
| 解答步数 | 列显式→挖隐式→分层枚举→计数（4 步） | 同 4 步 | 同 4 步 | 4 步（枚举方向重排） | 4 步（闭包推理→上界排除→搜索→报双段） |
| 数值规模 | 两位数答案、无高精度运算 | 同 | 同 | 同 | 同（个数一位数+内存四位整数） |

- 所有题都是"整数域上的约束满足枚举"，无超越计算、无浮点容差敏感性；单题冷启动的工作记忆负荷（需同时持有的约束数 4–5 条）相同量级。
- 各级都保留了"遗漏隐式约束 → 确定性多算"的探针（169/217/271/33 与 75/7），保证 lure 与 with-source 条件在每级都有可判别的失败模式。
- 冷启动难度自评均落 20–60% 区间：源题型是已知中等难度竞赛计数；L2 需两步表决语义推导；L3 需同时持有比例耦合与日历上限；L4 依赖闭包与互斥容易漏挖。注意：与 SPEC §7 缺口 2 一致，该区间目前是自评，需跑 target-only 基线实测校准；若某级实测偏出区间，优先调参数（总量/预算）而非改结构，以保持距离梯度不动。
- 预期检查（SPEC §2 约束 5）：本链 with-source 增益应满足 增益(L1) ≥ 增益(L2) ≥ 增益(L3) ≥ 增益(L4)；若出现倒挂，回查等级归属与本表的持平性假设。

## 机器可判协议

四题 answer_type：L1/L2/L3 为 numeric（精确整数，tolerance 0）；L4 为 string，判等前 strip 空白、分号两侧容忍空格（"6;2048"）。全部原创（provenance: original），实体与数值组合未见于常见语料。
